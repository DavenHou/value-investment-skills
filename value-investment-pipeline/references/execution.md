# 一键流水线执行规则

## -1. 缓存检查与运行模式

开始联网和调用下游skill前，先按[快速模式与公司缓存](fast-path-and-cache.md)定位“请求范围＋刷新深度”并验证缓存；该文件是模式条件的唯一来源，本页不再复制三种mode定义。

`scope=quick_valuation`仍运行纯现金覆盖、三年熊／基准／牛预测、归一化ROE／ROA、杜邦与盈利可靠性、估值、压力和退出；只跳过本页的背景／质量、行业同业和仓位步骤。上述均为内部计算，默认展示严格服从[user-company-query-format.md](user-company-query-format.md)的快速例外，只给核心决策卡与估值价格带。有效正式交接可以复用，新财报或口径失效则按选择器结果重建。历史`--as-of`只接受估值日当时可得的申报、预测输入、TTM、价格与退出样本。

先用`scripts/select_refresh_mode.py --scope ...`做结构和日期检查，再结合官方变化检查确定最终mode。脚本结果不能替代官方披露核验。运行结束后只更新发生变化的缓存模块，并保留各模块自己的证据截止日，不能用一次新价格把旧基本面日期整体改成当天。

## 0. 检索与交接原则

默认核心模式只检索能改变闸门、价格结论或行业择时的证据。缓存命中时限制为官方变化检查、当前价格，以及目标股和3–6只代表同业的批量20／60／120交易日价格与行业基准；不重新搜索已经缓存且仍有效的公司历史、商业模式和旧财报。缓存未命中或触发失效时，才取最新年报、最新中报／季报和重大治理公告。只在身份、口径、治理、现金归属、关联交易、盈利趋势或同业可比性存在实质疑点时扩展证据链。

下游skill只回传最小决策集，不回传完整文章：`status`、核心数值、证据截止日、一个最重要正面依据、一个最重要反证，以及下一阶段所需的输入字段。已有正式交接字段时不得由总控重新估算同名字段。

### 0.1 闭环补齐与标准化

一键查询遇到可恢复的会计或历史数据缺口时，必须在同一次运行内完成，而不是输出恢复清单。按影响链由上至下补齐：当前利润与税项 → TTM EPS／ROE／ROA → 三年熊／基准情景 → PR与价格带 → 历史峰值PR和`S/H/M` → 压力情景与仓位。

- 对非经常项目先查财报附注、业绩调节表、8-K／新闻稿和同期税务数据；若无披露的税后影响，使用同报告期`所得税费用 ÷ 税前利润`作标准化税率，计算税后项目影响。标注为“标准化税后调整”，并保留GAAP对照。
- 标准化税率只用于剔除已被正式披露为非经常项目的金额，不能延伸至正常经营项目；若项目税务处理已由公司单列，以公司单列值优先。
- 历史峰值逐个重复同一检索与调整规则；不得因历史资料工作量大就保留原始GAAP峰值、却与当前核心PR混用。未发现同类项目的样本调整值为零，并记录所查申报。
- 价格带和仓位使用估值 skill 的未扣非法定归母正式交接；标准化调整仅作非执行敏感性，不把调整后利润写回GAAP事实字段。重大一次性项目未解释清楚时暂停正式价格带。
- 仅当原始一手材料不可访问且无法得到同期间税费与税前利润，才记录`insufficient`。此为罕见异常；核心模式只说明缺少字段，不向用户提出研究待办。

## 1. 身份与数据截止日

确认法定公司、代码、交易所、股份类别、币种及A股／H股／港股／美股／ADS转换关系。检索当前官方披露、最近财报、业绩会、治理公告及同日市场价格；跨市场时另外核验汇率、投资路径税后股息、净回购、股权激励稀释和流动性；所有数据记录日期和口径。

## 2. 背景与质量闸门

使用`company-background-research`完成100分评分和否决闸门，但核心模式只保留保留一位小数的精确总分、评分证据截止日、状态、最强优势和最大反证。总分必须逐字读取正式`research_handoff`，不得由总控根据后续浏览结果重打分或用现金、估值、股价表现加分。找不到仍有效的正式分数时重新运行背景skill；仍不能取得则标为`insufficient`并停止，不输出约数。非金融企业调用`pure-cash-coverage`，但只回传严格净金融资产覆盖率和口径风险；现金覆盖不能代替业务质量。

先按毛利来源、客户购买目的和投资论点读取 `business_model_class`。纯科技公司读取三项完整 `technology_gate`；平台型零售、内容、电商、出行和本地生活等混合公司，只把不可替代性与自主议价能力作为平台附加闸门，成长性按行业交易、客户和单位经济评价。旧报告缺少结构化字段但正文已有充分同类证据时可以沿用精确总分并标明待补字段；关键证据缺失时先补充复核。批量快筛未通过适用闸门的公司只能列为“观察／待正式复核”。

只有以下条件同时满足才通过：

- `research_status: pass` 或 `pass_downgraded`（后者单股仓位上限 5%）；
- 总分及关键维度达到背景skill阈值；关键维度允许恰有一项低于最低线但不低于其 70%；
- 证据覆盖至少80%；
- 没有未解决的否决闸门。
- 纯科技 `technology_gate.status: pass`，三项均至少3分且合计至少10分；混合平台两个附加项均至少3分，且行业增长质量通过。

未通过时，后续结果只能是非执行性敏感性，流水线记录`stopped_at: background_research`。

## 3. 业绩预测

背景通过后，使用`company-earnings-forecast`建立公司类型适配的熊／基准／牛情景。给估值的交接必须包含未来三个完整财年的基准与熊市场景净利润、平均归母净资产、平均总资产、ROE和ROA；无法形成资产负债表路径时不得伪造ROE／ROA。核心模式默认只回传基准EPS区间、中性／悲观归一化ROE与ROA、熊市EPS下界和一个最重要驱动／失效条件；完整年度情景表仅在展开模式输出。

只有`forecast_status: usable`才进入估值。不得为了获得更低估值而随意压低或抬高盈利；每个情景必须有业务机制和来源。

## 4. 条件估值

使用`company-valuation-calculation`选择唯一动作口径。非周期股使用`PE_TTM ÷ 执行ROE`；周期股使用第二公式`100 × 同期PB ÷ 执行ROE²`。两者的执行ROE均直接消费估值 skill 的股息率选档、重大业绩下滑保护及正式归一ROE交接，再与各自当前可比风险锚取低。预测权重只在估值skill定义，本页不重算。`PE_TTM ÷ ROE_TTM`只是核验PR，不产生第二条动作线。

稳定股优先选`strict_stable`；候选不足时可另列`relaxed_stable`，但放宽只改变稳定性条件，不放宽质量、治理、预测或高ROE复核，累计仓位上限15%。当前TTM或三年任一ROE超过40%时，强制检查回购、净资产收缩、权益乘数、利息覆盖、ROA／ROIC和每股FCF；失真时把PR降为诊断项，不得直接把ROA代入PR公式。

批量筛选必须分两轮：第一轮对全部公司仅用`strict`策略跑完背景、预测、估值和风险全流水线，记录真正通过的严格候选数；只有该数量低于用户最低需求时，第二轮才对边缘公司运行`controlled_relaxation`。结果始终先排严格候选，放宽候选只补足缺口，不因估值更便宜反过来挤掉质量相当的严格候选。

非金融企业必须把ROE拆成净利率、资产周转率和权益乘数，报告TTM与三至五年中位数；数据允许时追加五因素杜邦。权益乘数较历史中位数上升超过25%、ROE升而ROA／ROIC降，或债务和利息覆盖恶化时，按历史正常权益乘数与压力融资成本重算ROE并设置杠杆复核闸门。金融企业改查监管资本、资产质量、拨备、流动性与信用成本。

周期股进入正式估值前增加四项检查：①用产品价格、订单／销量、库存、开工率、资本开支或产能利用率确认周期驱动；②用成本曲线、市场份额、低谷现金流、债务和资本纪律标记`leader／mainstream／high_cost_tail／uncertain`；③按产业证据把可比历史逐年标为`trough／recovery／boom／downturn`，四阶段不全时中性锚只能标`provisional`；④核验库存、固定资产／在建工程、商誉、资源资产、减值、少数股东权益和有息负债，防止低PB来自不可回收净资产。`high_cost_tail／uncertain`或资产质量未通过时，不因低PB生成可执行仓位。

周期股另建`cycle_fundamental_signal`，状态为`deteriorating／mixed／bottoming／recovering／insufficient`，证据来自需求、现货／期货价格或价差、库存与开工率、产能退出、资本开支和已落地的供给侧／反内卷政策。该状态进入行业宏观权重与仓位节奏，但必须与后续同业股价择时状态分列；股票止跌不得冒充产业触底，产业触底也不得抬高基础目标PR。

周期股用同日PB并列计算当前弱运行PR、完整周期PR和悲观PR，按估值skill生成`cycle_anchor_conflict`。`material_gap`最多保留4%信息风险首仓并锁定后续档；`regime_split`暂停新增，已有持仓默认减仓一半并进入退出复核；`insufficient`新增为0%。

核心模式必须输出`PE_TTM／ROE_TTM／PR_TTM`及配对口径、中性与悲观归一市赚率、预测基准市赚率及年度、公司自身滚动PR中位数和25／75分位、杜邦主驱动与杠杆状态、当前估值位置、各建仓候选区和一个估值失效条件。周期股另外逐档输出中性／悲观`目标PB = 目标PR × 归一化ROE² / 100`及对应价格；`1PB／0.5PB`只可作特定ROE下的速查校验。使用股东回报修正时同时展示基础与修正市赚率；成长股使用预测ROE时标注“情景辅助”。只有`valuation_status: valid`且杜邦／ROA可靠性风险已处理，才进入可执行退出监控。

## 5. 退出监控与压力情景

使用`fundamental-exit-monitoring`建立三至五条核心投资断言。分别判断基本面和估值状态；内部构造减弱与破坏情景，核心模式只展示会决定仓位上限的压力损失和最关键恢复／破坏触发器。

对已持有资产，用峰值日当时已公开的同口径财务数据重算历轮高点PR，建立`E = min(E_market, 个股历史峰值PR)`。港股／H股`E_market = c = 0.90 × (1 − 股息率 × 税率 ÷ 10%)`，A股／美股为`1.00`。PR跨档先触发复核；结合公司历史、最新同口径盈利和基本面状态确认后才执行对应估值减仓。

只有`pipeline_status: pass`、`fundamental_status: intact`且`add_permission: allowed`时，价格计划才可以标为当前可执行。`weakened/paused`时当前建议新增仓位为0%，但保留状态恢复后必须重新估值的预案。估值退出进入 `early_exit` 或更高阶段后至少暂停新增；`hard_exit`时禁止新增并输出退出阶梯。

## 6. 仓位与分批

进入仓位计算前，按[行业同业强弱与领先信号](industry-relative-timing.md)完成行业横向确认。该结果不是新的质量或估值闸门，但会约束首仓时点与本次新增比例：

- `bear_leading`：弱势组继续先创新低且行业广度恶化，目标股即使暂时抗跌也不得据此加仓；已进入估值区时取首仓区间下限或等待。
- `unconfirmed`：证据冲突或弱势组尚未止跌，保持估值计划但不追加择时仓。
- `bottoming_candidate`：至少两只可比弱势股先停止创新低，并出现相对强度和行业广度改善；目标股同时处于有效估值区并出现自身短期回落时，可解锁正常首仓，不解锁深度价值档。
- `recovery_confirmed`：弱势组、行业广度和目标股共同确认修复；仍按原估值和风险上限分批，不追高、不抬升目标价。

同业不足、停牌、流动性过低或被公司特有事件主导时标为`insufficient`，不把缺失证据解释为止跌。详细模式记录样本选择、窗口、信号日期和反证。

使用`portfolio-position-sizing`先形成估值驱动建议，再以压力损失和组合政策压缩：

```text
最终可执行仓位 = min(
  估值驱动建议，
  压力风险上限，
  35%单股硬上限，
  股票数量、行业、相关组、流动性和账户上限
)
```

先列仓位形成桥：当前市赚率对应的候选档、估值驱动累计仓位、本次新增仓位、压力上限、组合上限、最终采用值和瓶颈。随后每家公司使用各自阶梯表；每档按“价格下限、价格上限、对应市赚率、到上限需跌、到下限需跌、本档新增比例、完成后累计仓位、基本面解锁条件、当前状态”列示，不把多家公司压缩到同一行，也不得只给累计仓位。用户未给风险预算时，内部保留五档敏感性；核心模式只展示建议仓位及其隐含的压力损失，详细模式再展开全表。

## 7. 一致性检查

交付前核对：

- 运行模式与缓存命中状态明确；快速模式已经完成官方变化检查，且没有把价格日期冒充基本面证据日期；
- 被复用的背景、预测、估值和压力交接均有状态、来源指纹与各自截止日，任何失效模块已按正确模式重跑；
- 所有阶段是同一证券、股份类别和币种；
- 背景、预测、估值和价格的数据截止日没有错位；
- 业务模型分类与收入／毛利机制一致；纯科技或混合平台已显示适用闸门，且未用低估值、短期高增长或市场份额代替不可替代性与议价能力；
- 预测EPS、ROE、ROA与估值公式口径一致，归一化年份和权重已披露；ROA未被直接代入市赚率；
- 稳定企业的`PE_TTM`与`ROE_TTM`同截止日、同股份和同会计口径，完整TTM未被单季乘四替代；
- 稳定非周期企业已列出最近三个可比完整财年ROE、等权平均、标准差、变异系数和定性可比性；已标明`strict_stable／relaxed_stable／unstable`。`relaxed_stable`有严格候选数不足证据、15%累计仓位限制和后续财报重新确认日历；`unstable`未输出稳定股可执行单点PR；
- 当前TTM或最近三年任一ROE超过40%时，`extreme_roe_review_required`、`roe_reliability`、ROA／ROIC／FCF与回购／净资产／杠杆证据已完成；未完成或确认失真时PR只作诊断；
- 非金融企业已完成杜邦拆解；杠杆驱动ROE已按正常权益乘数重算，未用虚高ROE抬价或放仓；
- 周期股已确认周期驱动和公司角色，阶段标签有产业证据；中性ROE使用阶段平衡而非弱年份或近期加权，悲观ROE使用弱年份／熊市；净资产质量已核验；
- 周期股的产业信号与同业股价择时信号分别记录，没有互相代填；每档中性／悲观目标PB均由对应ROE和目标PR逐式计算，没有机械套用1PB／0.5PB；
- 周期股已用同日PB显示当前运行率／中性／悲观PR和锚分歧状态；`material_gap／regime_split`只限制一次动作，没有重复折价或机械减仓50%；
- 压力损失以同一当前价格计算；
- 建仓累计比例不超过风险上限和35%；
- 每档新增仓位之和与累计仓位一致，价格下限不高于价格上限，到下限跌幅不小于到上限跌幅；
- 每档市赚率区间与价格区间方向一致，并与比较表使用同一预测口径；
- 同业样本与目标公司业务、市场和周期暴露具有可比性，弱势组至少两只，且止跌结论同时满足价格、相对强度和行业广度条件；
- 同业信号只改变时点和首仓节奏，没有抬高估值价格带、覆盖基本面失败或解锁深度价值／极端错价仓；
- 当前价已进入更深估值档时，估值支持累计仓位、本次新增仓位和压缩原因均已分别披露；
- 当前持股数、全流程合格且低估的候选数和新增持仓后总数相互一致；5–8只是常态区间；
- 结论区已经完整回答“现在做什么、什么价格、多少仓位、何时加仓”。

## 8. 具体复核日历与跳空处理

只要估值已支持更高累计仓位、但风险或基本面尚未解锁剩余仓位，就必须为每一层剩余仓位给出具体复核日历，不能只写“下季财报后”或“等待验证”。每个复核点至少包含：`scheduled_at`、时区、复核事件、拟解锁的仓位层级、必查指标和日期状态。

- 官方已公告日期：使用官方日期，并把正式复核安排在材料发布且市场收盘后的首个用户时区工作日；标为`official_confirmed`。
- 官方尚未公告：不得把历史规律伪装成公司日程。先给一个检查官方日历的内部计划日，再给监管申报期限或合理窗口后的最迟复核日；分别标为`internal_checkpoint`、`regulatory_latest`或`estimated_window`。
- 若公司在计划日前提前披露，复核自动提前至正式材料发布后的首个用户时区工作日；原计划日取消，不重复计算。
- 同时设置日历、官方披露和价格三类触发器，最早发生者启动复核。价格触发器包括收盘价穿越任一市赚率档位边界，或较上次估值基准价变动达到默认8%；8%只是旧估值过期阈值，不是买卖信号。
- 依赖下一期财报的仓位至少列四个复核点：当前决策；官方披露日前第5个交易日收盘后的预检；正式材料发布后2小时内或下一常规交易时段开盘前的快审；完整监管报表可得后的首个用户时区工作日复核。发布日明显跳空时再列首个完整常规交易日收盘后的价格复核。
- 完整流水线已通过且唯一缺口是下一期经营确认时，可以在正常首仓额度和压力／组合上限内使用受限的信息风险首仓，不能因为“等待财报”机械保持0%，也不能额外增加财报押注仓。治理、现金归属、偿债、审计、重大客户流失或无法界定的跳空风险尚未解决时，首仓仍为0%。
- 财报后旧目标价自动失效。必须用新EPS、归一化ROE、股份数、行业宏观权重和新价格重算决策PR；基本面通过且新估值仍满足档位条件时才加仓，高于档位上沿则保留已有首仓、取消未执行额度并等待，不因财报好或开盘跳涨追价。
- 价格触发器可以要求立即重算PR，但不能代替基本面复核日，也不能自行解锁由财报验证控制的仓位；快审缺少完整现金流和资产负债表时不得解锁深度价值档或20%以上的集中层。
- 连续两期确认才能解锁的高仓位，必须分别列出第一期和第二期复核日；35%极端集中层另列最早复核日，不得与普通深度价值层合并。
