# 凯利参考仓位

## 0. 原始资料使用的形式（鲁成光式）

用户的原始资料用的是《股市赢家如是说》作者鲁成光从凯利公式推导出的等价形式，比标准凯利更直观：

```text
仓位 = (P1 × R1 + P2 × R2) / (R1 × |R2|)
     = 期望收益率 / (成功赔率 × 失败赔率)
```

- `P1 / P2`：成功、失败的概率，两者之和为 1；
- `R1`：成功时的赔率（赚几倍）；`R2`：失败时的赔率（亏几倍，取负值，分母取绝对值）。

原始资料的验证例：抛硬币，猜对赢 2 元、猜错亏 1 元。`P1=P2=0.5, R1=2, R2=-1`，分子 `0.5×2 + 0.5×(-1) = 0.5`，分母 `2×1 = 2`，仓位 `= 0.25`，即 25%。

这个形式与下文的标准凯利 `f = (p·b − q·a) / (a·b)` 完全等价，只是把分子直接读作"期望收益率"。**输出时优先用这个形式展示**，因为使用者能自己验算；标准凯利作为交叉检查。

分子为负（期望收益率为负）时仓位为 0，不做空、不反向下注。


凯利只是可选的仓位上限旁证，不是估值、基本面或压力损失的替代品。缺少凯利输入不会阻断原有压力损失流程；但不得凭主观“把握”、质量分、预测置信度或熊／基／牛情景权重冒充策略胜率。

## 1. 状态

`kelly_reference.status` 只允许：

- `usable`：同策略记录、结果定义、持有期、退出规则、样本截止日、原始／有效样本量和保守概率赔率都可追溯；
- `illustrative`：只是用户指定或模型情景敏感性，计算但不进入最终上限；
- `not_usable`：用户要求凯利分析，但样本、口径、尾部或相关性证据不足；
- `not_applicable`：本次不需要凯利。

`not_usable | not_applicable` 不产生凯利上限，也不得默认为0%或100%。

## 2. 二元公式

仅当每次决策可一致归类为“成功／失败”时使用：

```text
p = 成功概率
q = 1 - p
a = 成功时的净盈利倍数，正数
b = 失败时的亏损比例绝对值，0 < b ≤ 1

保守期望边际 E = p × a - q × b
全凯利 f* = E ÷ (a × b)
```

`b` 始终输入正的损失绝对值，不允许一方面把亏损写成负数、另一方面在分母取绝对值。例如`p=50%`、`a=2`、`b=1`，则`E=0.5`、`f*=25%`。

计算器同时输出未限制全凯利和0%–100%的现金／多头上限。本skill不因凯利结果默认使用融资或杠杆。`E≤0`时多头凯利参考为0%。

## 3. 多情景

熊市／基准／乐观等三个或更多结果不得硬压成二元胜率。对情景`i`的概率`p_i`和总回报倍数`r_i`，在不使用杠杆的前提下求：

```text
max  Σ[p_i × ln(1 + f × r_i)]
s.t. 0 ≤ f ≤ 1
     1 + f × r_i > 0
```

概率之和必须为100%，回报倍数不得低于`-1`。估值skill的情景权重默认只能得到`illustrative`；只有经同策略样本校准后才能升为`usable`。

## 4. 证据闸门

`usable`必须同时记录：

1. 标的／市场范围、进场条件、持有期和退出规则；
2. 概率来源、样本截止日、原始样本量和扣除重叠持有期／同一事件后的有效样本量；
3. 与同一策略和同一退出规则匹配的税费后盈利与亏损倍数；
4. 概率使用置信下沿，盈利倍数使用保守低端，亏损倍数使用保守高端；同时记录`probability_confidence_method`和`payoff_conservative_method`，并把`input_basis`标为`conservative`；
5. 尾部跳空、停牌、流动性和共同风险因子已单独进入压力损失与组合上限。

不使用单一固定样本数代替统计校准。必须披露样本边界与有效样本量；样本数多但口径不同、高度重叠或没有跨越必要市场阶段，仍不可用。

## 5. 分数凯利和最终上限

只要凯利被计算，同时展示全凯利、1/2凯利和1/4凯利。用户没有明确选择`adopted_fraction`时，三者都是敏感性，`cap_active=false`；不得默认选择全凯利、1/2或1/4凯利。

只有`status=usable`、`input_basis=conservative`且用户已选择`0 < adopted_fraction ≤ 1`时，分数凯利才作为额外上限：

```text
最终可执行累计仓位 = min(
  估值支持仓位,
  压力风险上限,
  已激活的分数凯利上限,
  35%,
  其他组合上限
)
```

凯利只能压低已经由估值与基本面解锁的仓位，不能提高估值档、解锁价格档或覆盖`paused | prohibited`。多个持仓共享风险因子时，不得把各自的单股凯利上限直接相加；优先使用联合压力损失和相关组剩余额度。

如果用户指定“财富回撤到某下限的概率不得超过某值”，使用带回撤概率约束的单独模型；不得用任意分数凯利声称已满足该概率。

## 6. 确定性计算

`scripts/calculate_position.py` 支持：

- 二元：`--kelly-win-probability-percent`、`--kelly-win-return-multiple`、`--kelly-loss-return-multiple`；
- 多情景：重复传入`--kelly-scenario PROBABILITY_PERCENT@RETURN_MULTIPLE`；
- 激活上限：`--kelly-status usable --kelly-input-basis conservative --kelly-adopted-fraction ...`，并同时传入可追溯的策略范围、样本、日期、概率置信方法、赔率保守方法、持有期和退出规则。

计算器只验证结构、算术和上限传导，不能证明用户提供的历史样本真实、可比或独立。

## 7. 旧规则与新规则对照

用户要求检验本次改造是否影响具体仓位时，用`--compare-legacy-rules`。旧规则固定为`pre_kelly_pre_evidence_stock_count_v1`：

- 不把凯利上限放入最终`min(...)`；
- 常态持仓区间为6–10只；新规则改为5–8只，9–10只仅在有明确例外证据时放行；
- 除此以外，必须使用完全同一组估值、压力损失、单股、行业、相关组、流动性和账户上限输入。

对照结果必须包含以下字段：

| 字段 | 含义 |
|---|---|
| `preferred_stock_count_range` | 旧规则`[6, 10]`与新规则`[5, 8]` |
| `old_rules.effective_cap_percent` / `new_rules.effective_cap_percent` | 两版最终仓位上限 |
| `effective_cap_delta_percent` | 新减旧；负值代表新规则压低仓位 |
| `binding_constraint` | 两版分别是哪条上限生效 |
| `new_position_slot_available` | 新建仓是否因持股数规则改变 |
| `kelly_decision_role` | `not_active` / `active_not_binding` / `binding_without_cap_change` / `binding_reduced_cap` |
| `change_reasons` | 可追溯的规则变更原因 |

这是规则对照，不是事后收益回测；两版在比较中不得使用不同的价格日期、未来信息或不同退出规则。
