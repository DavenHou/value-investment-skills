# 仓位控制方法

## 1. 必需输入

| 输入 | 定义 | 缺失时处理 |
|---|---|---|
| portfolio_value | 同一币种的组合净值 | 无法输出金额，只能输出比例 |
| risk_budget_percent | 用户愿意让单公司压力情景损失占组合净值的上限 | 不代替用户设定，只做多档敏感性 |
| current_weight_percent | 当前公司市值占组合净值比例 | 无法判断是否超限 |
| position_handoff | 基本面、估值、许可、两类压力情景 | 接口不完整则结果不可执行 |
| portfolio_caps | 单股、行业、相关组、流动性及账户上限 | 只输出风险公式上限 |
| valuation_bands | 当前估值位置、首仓／加仓候选价格带 | 无法输出条件化建仓价格 |
| valuation_reliability | 估值状态、公司历史、杜邦与ROA可靠性 | 关键输入未解决时不得把PR候选档转为可执行仓位 |
| dupont_leverage_status | ROE主驱动、权益乘数及正常杠杆重算 | 未处理的杠杆驱动暂停新增 |
| current_stock_count | 当前股票持仓数量 | 可输出个股方案，但无法判断建仓后是否偏离5–8只常态区间 |
| qualified_undervalued_count | 当前通过全流程且进入买入区的独立候选数 | 不为凑满5只或8只而假定存在候选 |
| market_listing | A股、港股／H股、美股／ADS及投资路径 | 无法应用市场偏好、税务和流动性校准 |

所有百分比输入都使用百分数，例如 `1.0` 表示 1%，`30` 表示 30%。压力损失必须与当前仓位使用同一证券、币种和价格日期。

## 2. 情景选择

- **破坏情景**：用于控制核心论点被证伪时的单公司损失，通常是长期仓位上限的主口径；
- **减弱情景**：用于观察逻辑尚未完全证伪时，暂停加仓会暴露多少组合损失；
- 若重大治理、流动性或停牌风险不能反映在价格区间内，把结果标为 `gap_risk_unbounded`，不得把公式上限称为安全上限。

同一情景给出损失区间时，用高损失端计算保守上限，用低损失端做敏感性。不要把两端包装成建议持仓区间。

## 3. 公式与示例

假设组合净值 100 万，单公司风险预算 1%，破坏情景损失 50%–60%：

```text
压力损失预算 = 1,000,000 × 1% = 10,000
保守风险仓位上限 = 1% ÷ 60% = 1.67%
敏感性上限 = 1% ÷ 50% = 2.00%
对应持仓金额 = 16,667 至 20,000
```

可执行上限只取 1.67%，然后再与集中度、流动性等其他上限比较。2.00% 只是较轻压力端的敏感性，不是下限。

## 4. 状态闸门

| 条件 | 新增风险 | 现有仓位处理 |
|---|---|---|
| intact + allowed + 估值有效 + 杠杆已处理 | 可计算可执行上限 | 与上限比较 |
| weakened 或 paused | 不增加 | 计算压力暴露；超限则启动降险评估 |
| broken 或 prohibited | 禁止 | 启动退出评估，不机械给止损价 |
| insufficient / unpriceable | 暂停 | 补证据；仅做标注为不可执行的情景 |
| immediate review | 暂停 | 先完成事件复核 |

动作闸门决定能否交易，公式只决定在允许时最多承担多少风险。

即使闸门暂停，也要给条件化预案，但必须满足：当前建议仓位为0%；每一档标注“状态恢复后重新估值才生效”；不能把预案写成挂单指令。

## 5. 组合约束

至少检查：

1. 单一公司总仓位；
2. 同行业、同主题、同宏观因子的聚合仓位；
3. 高相关持仓在同一压力情景下的联合损失；
4. 日均成交、停牌或跨市场结算带来的退出时间；
5. 现金储备、杠杆、税务和账户限制。
6. 单股35%硬上限、5–8只常态持股区间和合格低估机会数。
7. 市场偏好系数、税后股东回报、汇率和实际可退出天数。

若多个持仓共享同一风险因子，应先合并压力损失，再分配个股风险预算，不能对每只股票重复使用完整预算。

## 6. 风险预算不是默认参数

风险预算反映用户能承受的组合损失，不能根据公司名气或模型置信度暗中替用户决定。用户尚未提供时，按用户政策列出0.5%、1%、2%、3%、5%的纯敏感性结果，并明确它们不是推荐值。

## 7. 估值建议与可执行仓位

估值价格带先形成组合架构建议，再用风险上限压缩：

```text
PR候选累计仓位 = 首仓 + 已满足PR条件的加仓档
估值驱动建议 = PR候选累计仓位，受估值状态、杜邦／ROA可靠性和公司历史约束
风险验证仓位 = 风险预算率 / 压力损失率
市场校准仓位 = 估值驱动建议 × 市场偏好系数
最终可执行累计仓位 = min(市场校准仓位, 风险验证仓位, 35%, 其他组合上限)
```

若`valuation_status`不是`valid`，或`leverage_review_required=true`却没有正常杠杆ROE，`估值驱动建议=0%`，PR价格带只保留为非执行观察。例如估值建议累计10%，但破坏情景损失60%，则该持仓可能造成组合净值6%的压力损失。只有用户明确接受至少6%的单公司风险预算且其他约束允许时，10%才通过风险验证。

## 8. 分批价格跌幅

每档价格区间的两端分别相对同一当前价格计算：

```text
较现价变动 = (档位价格 / 当前价格 - 1) × 100%
```

对低于现价的建仓区，展示为“较现价下跌X%–Y%”；若区间包含高于现价的价格，使用“变动区间”而不误写成下跌。当前价格日期必须与估值日接近。

## 9. 分批建仓的压力损失

分批买入不是一次性满仓。压力计算必须同时区分三件事，不能把其中任何一个替代另一个：

1. **已成交单档的路径／跳空风险**：对每一档已成交资金 `w_i` 和成交价 `P_i`，在破坏价 `P_s` 的损失为 `w_i × (1 - P_s / P_i)`；未成交的低位档不能降低这部分已承受风险。
2. **假设全部计划档均已成交的阶梯成本**：当 `w_i` 是组合净值的现金配置比例时，完整阶梯的每股加权平均成本为 `C̄ = Σw_i / Σ(w_i / P_i)`，不是简单的价格算术平均；完整阶梯价格损失为 `1 - P_s / C̄`。
3. **完整阶梯对组合的损失**：`Σ[w_i × (1 - P_s / P_i)]`。这和“完整阶梯价格损失”不同，前者直接对应组合净值。

输出必须分别给出首仓（或所有已成交档）、假设完整阶梯、以及“价格跳过未成交低位档”的路径风险。分批可以降低完整阶梯的平均成本，但不能以尚未成交的摊低成本绕过风险预算、基本面闸门或退出复核。

## 10. 版本与复核

记录计算日期、接口版本、组合净值日期、所用情景、全部上限及最终瓶颈。下列任一变化都需重算：退出状态改变、压力损失区间改变、价格或组合净值显著变化、行业相关性上升、流动性恶化或用户风险预算调整。
